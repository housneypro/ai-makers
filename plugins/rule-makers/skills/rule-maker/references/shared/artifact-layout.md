# 산출물 구조와 독립성

## 1. 작업 디렉터리

중간 산출물은 스킬을 호출한 작업 디렉터리의 `.makers/<종류>/<이름>/`에 둔다. git으로 추적한다.

- `<종류>`: `goal` | `skill` | `agent` | `rule`
- `<이름>`: 만들 대상의 이름. 소문자·숫자·하이픈만 쓴다.

```
.makers/<종류>/<이름>/
  plans/00-<이름>-plan.md
  spec/01-<영역>.md …           공유 인터페이스가 있으면 00-contracts.md 먼저
  impl_plans/01-<단위>.md …     문서가 둘 이상이면 00-overview.md 추가
  backlog.md                    미포함 판정 항목이 있을 때만
  cross-review/R<n>-request.md, R<n>-response.md
  goal.md                       종류가 goal일 때만
```

세 단계 디렉터리는 항상 만든다. 대상이 작으면 디렉터리마다 파일 하나로 끝난다.

## 2. 번호와 분할

- 파일 이름은 `NN-<소문자-하이픈>.md`다. `00`은 그 단계 전체를 묶는 문서(plan·contracts·overview)에만 쓴다.
- 나누는 기준은 파일 수가 아니라 규모와 소유 경계다. 한 파일이 2,000행을 넘을 것 같거나
  서로 독립적으로 쓸 수 있는 영역이 뚜렷할 때만 나눈다.
- 둘 이상의 파일이 공유하는 이름·값(인터페이스, 필드, 식별자, 공통 상수)이 있으면
  그 단계의 `00-contracts.md`에 먼저 확정한 뒤 나머지를 쓴다. 나머지 파일은 계약을 인용만 하고 다시 정의하지 않는다.
  공유하는 것이 없으면 계약 문서를 만들지 않는다.
- A가 B의 내용을 입력으로 삼으면 둘을 동시에 쓰지 않는다. B를 먼저 끝낸다.
- 여러 파일을 병렬로 썼으면 수렴리뷰에 교차정합 관점을 더한다.

인용 규약:

| 대상 | 규약 |
|---|---|
| 대상 프로젝트의 파일 | 그 프로젝트 루트 기준 상대 경로. 줄 번호를 붙일 수 있다(`src/a.ts:12`). |
| 같은 묶음의 다른 문서 | 그 문서 기준 상대 경로 + 절 번호 또는 식별자. **줄 번호는 쓰지 않는다**(라운드마다 밀린다). |

대상 프로젝트의 파일 전문을 베껴 넣지 않는다. 바꿀 부분과 위치만 적는다.

부분 쓰기 탐지: 각 문서의 마지막 줄은 `END OF FILE`이다. 이 줄이 없으면 미완성으로 본다.
최종 산출물(스킬 파일, 에이전트 파일, 지침 파일)에는 넣지 않는다.

## 3. 문서 헤더

plans·spec·impl_plans의 각 문서는 맨 위에 다음을 둔다.

```markdown
# <제목>

- 이름: <이름> · 종류: goal | skill | agent | rule · 단계: plans | spec | impl_plans
- 수렴 상태: 작성 중 | 수렴 | 미수렴
- 리뷰 기록:
  - R1: 결함 n(C/H/M/L) · 반영 n · backlog n · 기각 n      ← 번호는 이어서 매긴다. 추가 횟수를 받아도 다시 세지 않는다
  - 범위 계약 개정: 없음 | <사유>
  - 교차 검증: PASS(R<n>) | 건너뜀 — <사유> | 미수렴      ← plans 문서에만
```

## 4. 독립성

최종 산출물은 makers 없이도 그대로 동작해야 한다. 만든 자리에서 쓰든 다른 프로젝트로 옮기든 같다.

**이식 단위**

| 종류 | 이식 단위 | 놓이는 곳 |
|---|---|---|
| goal | `plans/`·`spec/`·`impl_plans/`·`goal.md` 묶음 | `.makers/goal/<이름>/` |
| skill | 스킬 디렉터리 하나 | 출력 위치 아래 `<이름>/` |
| agent | 에이전트 정의 파일들 | 출력 위치 아래 호스트별 경로 |
| rule | 지침 파일 | 출력 위치(대상 프로젝트)의 호스트별 경로 |

**규칙**

- 이식 단위 안의 문서는 이식 단위 밖을 참조하지 않는다. skill·agent·rule 산출물은 `.makers/`를 참조하지 않는다.
  goal 묶음은 묶음 안에서만 상대 경로로 서로 참조하고, `backlog.md`·`cross-review/`는 참조하지 않는다.
- makers 플러그인·makers 저장소·Orca가 설치돼 있다고 전제하지 않는다.
- 생성 당시의 절대 경로를 넣지 않는다. 대상 프로젝트의 파일은 그 프로젝트 루트 기준 상대 경로로 적는다.
- 산출물이 다른 도구·스킬·환경을 필요로 하면 산출물 안에 전제 조건으로 명시한다.
- 금지하는 것은 **이번 생성 작업에 대한 의존**이다. 대상 프로젝트가 스스로 쓰는 경로·도구·정책을 설명하는 내용은
  의존이 아니다. 예를 들어 rule 산출물이 대상 프로젝트의 규칙으로서 그 프로젝트의 `.makers/` 디렉터리나
  그 프로젝트가 제공하는 스킬을 언급하는 것은 허용한다. 기존 규칙을 지키려고 경로를 흐리게 고쳐 쓰지 않는다.

**기계 검사** — 최종 산출물을 확정하기 전에 이식 단위 전체를 검색한다.

| 찾는 것 | 허용 |
|---|---|
| `.makers/` | goal 묶음에서 자기 묶음을 설명하는 문장에만. skill·agent·rule은 이번 작업의 중간 문서(`.makers/<종류>/<이름>/`)를 가리키는 것 0건. 대상 프로젝트의 규칙으로서 언급한 것은 하나씩 확인해 제외한다 |
| 절대 경로: 드라이브 문자(`C:\`), 루트(`/`로 시작), 홈(`~`), 네트워크 경로(역슬래시 두 개로 시작) | 0건. URL이나 슬래시로 시작하는 명령 이름처럼 경로가 아닌 것은 하나씩 확인해 제외한다 |
| 대상 프로젝트의 파일을 가리키는 경로 | 모두 프로젝트 루트 기준 상대 경로 |
| `backlog.md`, `cross-review` | 0건 |
| 산출물을 만든 maker 스킬(`goal-maker` 등)이 있어야 동작한다는 의존 | 0건. 대상 프로젝트의 구성 요소로서 언급한 것은 하나씩 확인해 제외한다 |
| goal 묶음 문서의 마지막 줄 `END OF FILE` 누락 | 0건 |

검사에 걸리면 고친 뒤 다시 검색한다. 걸린 채로 확정하지 않는다.

## 5. 이미 있는 파일을 바꿀 때

산출물을 생성할 위치에 같은 파일이나 디렉터리가 이미 있으면, 생성하기 전에 다음을 한다.

1. 기존 내용과 새 내용의 차이를 사용자에게 보인다. 유지·수정·삭제·추가되는 것을 구분한다.
2. 사용자의 확인을 받는다. 확인 없이 덮어쓰거나 지우지 않는다.
3. 사용자가 거절하면 생성하지 않고, 다른 이름·위치로 할지 중단할지 묻는다.

조사 단계에서 "새로 만들기로" 합의했더라도 이 확인을 생략하지 않는다. 그때는 바뀔 내용이 아직 없었다.
자기 작업의 중간 문서(`.makers/<종류>/<이름>/` 아래)를 고쳐 쓰는 것에는 적용하지 않는다.
다만 같은 이름의 이전 작업이 남아 있으면 이어서 할지 새로 할지 먼저 묻는다.
