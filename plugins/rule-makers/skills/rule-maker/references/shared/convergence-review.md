# 수렴리뷰

plans·spec·impl_plans 각 단계의 산출물을 다음 단계로 넘기기 전에 수행한다.
리뷰 항목의 반영 여부 판정은 [triage.md](triage.md)를 따른다.

## 1. 리뷰어

관점마다 독립 리뷰어를 하나씩 둔다. 호스트가 하위 에이전트의 병렬 실행을 지원하면 동시에 띄우고,
지원하지 않으면 관점을 하나씩 차례로 수행하되 관점마다 처음부터 다시 검토한다.

리뷰어의 독립성을 지킨다.

- 리뷰어에게 주는 것: 대상 문서 경로, 판정 기준이 되는 문서(이전 단계 산출물·범위 계약)와 대상 프로젝트 경로,
  맡은 관점의 정의, §3의 보고 형식.
- 주지 않는 것: 작성자의 논거와 대화 맥락, 다른 리뷰어의 평가. 호스트의 하위 에이전트가 기본으로
  부모 대화를 이어받는다면 이어받지 않도록 띄운다.
- 리뷰어는 문서를 고치지 않고 보고만 한다.

## 2. 관점

| 관점 | 묻는 것 |
|---|---|
| 정합성 | 인용한 사실(경로·값·명령·이름)이 실제 대상과 이전 단계 산출물에 일치하는가. 내부 모순이 없는가. |
| 최소성 | 각 결정·단계·검증이 범위 계약 안에 있고 완료 기준에 필요한가. 이미 있는 것으로 되는데 새로 만들고 있지 않은가. |
| 완결성 | 다음 단계 작성자나 실행자가 이 문서만으로 진행할 수 있는가. 빠진 단계·전제·파일이 없는가. |
| 구현가능성 | 그대로 실행하면 동작하는가. 순서·부작용·환경 함정이 없는가. |
| 교차정합 | 여러 파일을 나눠 썼을 때만. 파일 간 공통값·상호 참조·소유 경계가 일관된가. |
| 독립성 | 최종 산출물을 다루는 단계에서만. 이식 단위만 다른 곳으로 옮겨도 그대로 수행할 수 있는가. |

단계별로 어떤 관점을 쓰는지는 각 스킬의 `SKILL.md`가 정한다.
사용자가 "빠르게"를 요청하면 관점을 줄이고 "철저히"를 요청하면 늘린다. 정합성과 완결성은 줄이지 않는다.

판정 기준은 범위 계약, 이전 단계 산출물, 대상 프로젝트의 실제 파일이다.
같은 라운드에 함께 고쳐지는 형제 문서의 현재 내용을 근거로 결함을 내지 않는다.

## 3. 보고 형식

리뷰어는 항목마다 다음을 적는다.

```
- [CRITICAL|HIGH|MEDIUM|LOW] <위치: 파일 + 절 또는 식별자>
  근거: <무엇이 왜 틀렸거나 빠졌는가. 확인한 사실>
  수정: <한 줄>
```

- CRITICAL: 그대로 두면 산출물이 수행 불가이거나 잘못된 결과를 만든다.
- HIGH: 실행자가 막히거나 잘못 판단할 가능성이 높다.
- MEDIUM: 혼란이나 비효율을 낳지만 수행은 된다.
- LOW: 표현·형식.

결함을 찾지 못한 관점은 "결함 없음"이라고 명시한다. 추측으로 항목을 만들지 않는다.

## 4. 라운드 진행

1. 리뷰어 보고를 모아 중복을 없애고 [triage.md](triage.md)로 판정한다.
2. 문서 결함을 반영한다. 본문을 고치면 요약·체크리스트·`미확인·이견` 절도 함께 맞춘다.
3. 반영이 크면 다음 라운드를 돈다. 작으면 고친 부분만 한 번 재확인한다.
4. 2라운드부터는 직전 라운드의 변경분과 그 영향 범위만 본다. 계약 문서(`00-contracts.md`)가 바뀐 라운드는
   바뀐 식별자를 인용하는 파일까지 넓힌다.
5. 라운드를 거쳐도 CRITICAL+HIGH 건수가 줄지 않으면 개별 반영을 멈추고 결함을 유형별로 센다.
   한 유형이 과반이면 그 유형을 낳는 구조(계약 문서·인용 형식·소유 경계)부터 고친다.

**수렴** = 문서 결함 CRITICAL·HIGH 0건, 그리고 모든 확장 제안이 backlog에 등재됨.
MEDIUM·LOW 문서 결함은 수렴 조건이 아니지만 가능한 만큼 반영한다.
수렴하지 않은 단계에서 다음 단계로 넘어가지 않는다.

## 5. 라운드 상한

- 기본 상한은 3라운드다. 리뷰어를 띄워 보고를 받고 반영하는 한 바퀴가 1라운드다.
- 3라운드 안에 수렴하면 거기서 끝낸다.
- 3라운드를 다 쓰고도 수렴하지 못하면 진행을 멈추고 사용자에게 추가로 수행할 라운드 수를 묻는다.
  물을 때 남은 CRITICAL·HIGH 결함 요약과 함께 다음 두 가지를 반드시 안내한다.
  - 추가 횟수는 상한이다. 수렴하면 남은 횟수와 무관하게 즉시 끝낸다.
    (예: 100회를 받아도 5회째에 수렴하면 5회에서 끝난다.)
  - 추가 횟수를 받으면 라운드 카운트는 0부터 다시 센다.
- 추가 횟수도 다 쓰면 같은 방식으로 다시 묻는다.
- 다시 세는 것은 상한 판정용 카운트뿐이다. 리뷰 기록의 라운드 번호(R1, R2, …)는 그 단계의 처음부터
  이어서 매긴다. 추가 횟수를 받은 뒤의 첫 라운드는 R1이 아니라 직전 번호의 다음 번호다.
- 사용자가 추가 라운드를 주지 않으면 그 단계를 미수렴으로 기록하고 멈춘다. 수렴했다고 보고하지 않는다.

## 6. 기록

단계 산출물의 헤더에 리뷰 기록을 남긴다([artifact-layout.md](artifact-layout.md) §3).
라운드별 결함 수, 반영 수, backlog 등재 수, 기각 수, 범위 계약 개정, 최종 수렴 상태를 적는다.
사용자에게 추가 횟수를 받았으면 그 시점과 받은 횟수도 적는다.
