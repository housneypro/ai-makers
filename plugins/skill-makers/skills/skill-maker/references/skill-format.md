# 스킬 형식과 단계별 문서

## 1. 스킬의 형식

스킬은 디렉터리 하나다. 디렉터리 이름이 스킬 이름이다.

```
<이름>/
  SKILL.md        필수. 프런트매터 + 본문
  references/     선택. 필요할 때만 읽는 상세 문서
  scripts/        선택. 에이전트가 실행하는 스크립트
  assets/         선택. 템플릿 등 출력에 쓰는 파일
```

`SKILL.md`의 프런트매터:

```yaml
---
name: <이름>            # 디렉터리 이름과 같다. 소문자·숫자·하이픈
description: <설명>     # 한 문단. 아래 규칙
---
```

description 규칙 — 에이전트는 이 설명만 보고 스킬을 로드할지 정한다.

- 무엇을 하는 스킬인지와 **언제 써야 하는지**를 적는다. 사용자가 실제로 쓸 표현을 넣는다.
- 쓰면 안 되는 비슷한 상황이 있으면 함께 적는다.
- 스킬의 절차를 요약하지 않는다. 요약이 있으면 에이전트가 본문 대신 요약을 따른다.
- 3인칭 서술로 쓴다.

본문 규칙:

- 에이전트가 따를 절차와 판단 기준을 적는다. 에이전트가 이미 아는 일반 지식은 적지 않는다.
- 호스트 중립적으로 쓴다. 특정 호스트의 도구 이름을 전제하지 않고 행위로 적는다.
- 짧게 유지한다. 상세·예시·표가 길어지면 `references/`로 빼고, 언제 읽어야 하는지와 함께 링크한다.
- 스킬 안의 경로는 `SKILL.md` 기준 상대 경로다. 설치 위치를 가정하지 않는다.
- 스킬이 필요로 하는 것(명령, 다른 도구, 환경)은 본문 앞쪽에 전제 조건으로 적고, 없을 때 어떻게 할지도 적는다.
- 스크립트는 에이전트가 매번 다시 짜면 틀리기 쉬운 결정론적 작업에만 둔다. 실행 방법과 입출력을 본문에 적는다.

## 2. plans — `plans/00-<이름>-plan.md`

[shared/artifact-layout.md](shared/artifact-layout.md) §3의 헤더로 시작하고 `END OF FILE`로 끝난다.
해당 없는 절은 지우지 않고 한 줄로 사유를 쓴다.

| # | 절 | 내용 |
|---|---|---|
| 1 | 문제와 완료 기준 | 이 스킬이 해결할 반복 문제. 스킬이 없을 때 에이전트가 틀리는 지점. 완료 기준 목록 |
| 2 | 조사 결과 | 기존 유사 스킬, 작업의 실제 수행 방법, 필요한 명령·도구의 실재 여부 |
| 3 | 사용 시나리오 | 로드돼야 하는 발화 3개 이상, 로드되면 안 되는 비슷한 발화 2개 이상, 시나리오별 기대 결과 |
| 4 | 결정표 | D-ID · 결정 · 근거. 스킬 하나로 할지, 스크립트를 둘지, 무엇을 references로 뺄지 등 |
| 5 | 범위 계약 | 스킬이 하는 일 / 하지 않는 일 ([shared/triage.md](shared/triage.md) §1) |
| 6 | 검증 매트릭스 | 완료 기준 ↔ 확인 방법 1:1 |
| 7 | 리스크 | 남는 리스크와 수용 사유 |
| 8 | 미확인·이견 | 없으면 "없음" |

완료 기준에는 최소한 다음이 들어간다.

- 사용 시나리오의 로드돼야 하는 발화에서 description만으로 이 스킬이 선택된다.
- 스킬 디렉터리만 받은 에이전트가 각 시나리오의 기대 결과에 도달한다.

## 3. spec — `spec/01-<이름>.md`

- 프런트매터: `name`과 description 최종 문구. 문구가 plans의 어느 시나리오를 덮는지 표시한다.
- 전제 조건: 스킬이 필요로 하는 것과 없을 때의 동작.
- 절차: 에이전트가 따를 단계. 단계마다 입력·행위·판단 기준·결과.
- 파일 구성: 만들 파일 목록과 각 파일의 역할. references마다 "언제 읽는가".
- 스크립트: 있으면 실행 방법·인자·출력·실패 시 동작.
- 근거가 된 plans의 결정(D-ID), 미확인·이견.

## 4. impl_plans — `impl_plans/01-<이름>.md`

- 생성할 파일마다 절 하나: 출력 위치 기준 상대 경로와 **파일 전문**.
- 생성 순서와 생성 후 확인(파일 존재, 프런트매터 형식, 스크립트 실행).
- plans 검증 매트릭스의 완료 기준마다 확인 절차.
- 완료 체크리스트.

파일 전문은 그대로 복사해 쓸 수 있어야 한다. "적절히 채운다" 같은 자리표시자를 남기지 않는다.

## 5. 시나리오 확인

스킬을 생성한 뒤 수행한다. 스킬이 실제로 쓰이는 조건을 재현하는 것이 목적이다.

1. 독립 에이전트를 띄운다. 이 대화의 맥락과 `.makers/` 문서는 주지 않는다.
2. 생성된 스킬 디렉터리의 경로와 plans의 사용 시나리오 발화 하나를 준다.
3. 에이전트가 스킬을 따라 도달한 결과를 시나리오의 기대 결과와 비교한다.
4. 로드돼야 하는 발화 각각과, 로드되면 안 되는 발화 중 하나 이상에 대해 반복한다.
   로드되면 안 되는 발화에서는 description만 보여 주고 이 스킬을 쓰겠는지 묻는다.

호스트가 독립 에이전트를 띄울 수 없으면 건너뛰고 마무리 보고에 적는다.
기대 결과와 어긋나면 [shared/triage.md](shared/triage.md)로 판정해 반영하고, 고친 시나리오만 다시 확인한다.
