# village-coop-agent — 교동마을·갯마을 조합 업무 개선 에이전트 계획 초안

- 이름: village-coop-agent · 종류: agent · 단계: plans
- 수렴 상태: 작성 중 (초안. 수렴리뷰 전)
- 리뷰 기록:
  - 아직 없음
  - 범위 계약 개정: 없음
  - 교차 검증: 아직 수행하지 않음

> 미션 브리프만을 근거로 쓴 초안이다. 브리프에 없는 내용은 **가설**로 표시하거나 §8에 미확인으로 남겼다.
> 가설과 미확인 항목이 관계자 대화로 확정되기 전에는 수렴리뷰와 다음 단계(spec)로 넘어가지 않는다.

## 1. 문제와 완료 기준

**맡을 역할.** 제철 농산물을 다루는 교동마을 조합과 수산물을 다루는 갯마을 조합의 업무를 돕는 에이전트.
조합 담당자가 맡긴 업무를, 검증·정제된 조합 데이터를 근거로 처리해 결과를 돌려준다.

**전담 에이전트가 없을 때의 문제.** 미확인. 어떤 업무가 왜 힘든지는 브리프에 없고,
마을 관계자와 대화해 찾아야 한다(§8 U-01). 아래 시나리오의 업무는 모두 가설이다.

**완료 기준.**

- C-1. 위임돼야 하는 작업(§3)에서 description만으로 이 에이전트가 선택된다.
- C-2. 지시문과 위임 입력만 받은 에이전트가 §3 각 시나리오의 기대 결과를 돌려준다.
- C-3. 에이전트가 답의 근거로 쓴 데이터 항목과 출처를 결과에 밝힌다. 데이터에 없는 내용을 지어내지 않는다.
- C-4. 교동마을(농산물) 사례와 갯마을(수산물) 사례를 모두 처리한다.
- C-5. 데이터가 없거나 서로 어긋나는 경우, 추측으로 답하지 않고 그 사실을 보고한다.

## 2. 조사 결과

**근거 자료.** 미션 브리프 한 건.

| # | 브리프에서 확인한 사실 |
|---|---|
| F-1 | 무대는 두 마을이다. 교동마을은 제철 농산물, 갯마을은 수산물을 다룬다. |
| F-2 | 문제는 마을 관계자들과의 대화로 발굴한다. |
| F-3 | 획득한 데이터는 수집·검증·정제를 거친다. |
| F-4 | 만들 것은 두 마을 조합의 업무를 개선하는 AI 에이전트다. |

- **기존 유사 에이전트**: 확인할 대상이 없다. 사용할 호스트와 출력 위치가 정해지면 조사한다(§8 U-03).
- **역할의 실제 수행 방법**: 미확인. 조합의 현재 업무 흐름을 모른다(§8 U-02).
- **필요한 도구·권한**: 가설 — 정제된 데이터 파일 읽기만 필요하다. 쓰기나 외부 발송이 필요한지는 선정한 업무에 달렸다(§8 U-01).
- **대상 호스트의 형식 확인**: 아직 하지 않았다. 대상 호스트가 정해지면 확인한다(§8 U-03).

## 3. 위임 시나리오

전부 가설이다. 관계자 대화 뒤에 실제 업무로 바꾼다.

**위임돼야 하는 작업**

| # | 작업 (가설) | 입력 | 기대 결과 |
|---|---|---|---|
| S-1 | 교동마을 조합의 이번 주 출하 가능 품목과 물량을 정리해 달라 | 정제된 생산·재고 데이터 | 품목별 물량 표와 근거 데이터 항목 |
| S-2 | 갯마을 조합의 어종별 입고량과 판매량을 비교해 남는 물량을 알려 달라 | 정제된 입고·판매 데이터 | 어종별 차이와 근거 데이터 항목 |
| S-3 | 두 조합 데이터에서 서로 어긋나는 기록을 찾아 달라 | 정제 전후 데이터와 검증 기록 | 어긋나는 항목 목록과 각 출처 |

**위임되면 안 되는 작업**

| # | 작업 | 이유 |
|---|---|---|
| N-1 | 일반 소비자에게 제철 음식 조리법을 추천해 달라 | 조합 업무가 아니다 |
| N-2 | 조합 데이터와 무관한 일반 지식 질문에 답해 달라 | 조합 데이터를 근거로 하는 역할이 아니다 |

## 4. 결정표

| D-ID | 결정 | 근거 |
|---|---|---|
| D-01 | 에이전트의 구체 업무는 관계자 대화가 끝난 뒤에 확정한다. 대화 전에는 §3을 가설로만 둔다. | F-2 |
| D-02 | 에이전트는 검증·정제된 데이터만 근거로 쓴다. 정제 전 데이터나 추측으로 답하지 않는다. | F-3 |
| D-03 | 답마다 근거 데이터 항목과 출처를 밝히는 것을 출력 계약에 넣는다. | F-3, C-3 |
| D-04 | 권한은 읽기 전용에서 시작한다. 선정한 업무가 쓰기를 요구할 때만 넓힌다. | 최소 권한. 업무 미확정(U-01) |
| D-05 | 두 마을을 에이전트 하나로 다룰지 마을별로 나눌지는 보류한다. | U-04 |
| D-06 | 대상 호스트, 모델 지정 여부, 출력 형식은 보류한다. | U-03 |

## 5. 범위 계약

| 구획 | 내용 |
|---|---|
| 하는 일 | 두 조합 담당자가 맡긴 조합 업무를 정제된 데이터를 근거로 처리하고, 근거와 함께 결과를 돌려준다. |
| 하지 않는 일 | 관계자 인터뷰 자체, 데이터 수집·검증·정제 작업 자체(에이전트를 만들기 전에 사람이 하는 일이다). 조합 업무가 아닌 요청. 데이터에 없는 내용의 추정. |

데이터 수집·검증·정제를 에이전트의 역할에 넣을지는 이견이 있을 수 있다(§8 이견).

## 6. 검증 매트릭스

| 완료 기준 | 확인 방법 |
|---|---|
| C-1 | §3의 위임돼야 하는 작업 각각과 위임되면 안 되는 작업 하나 이상에 대해, description만 보여 주고 이 에이전트를 쓸지 판단하게 한다. |
| C-2 | §3의 시나리오를 실제로 위임해 결과를 기대 결과와 비교한다. |
| C-3 | 결과의 각 수치·주장에 데이터 항목과 출처가 붙어 있는지 본다. 근거 없는 것이 0건이어야 한다. |
| C-4 | 교동마을 사례와 갯마을 사례를 각각 하나 이상 위임한다. |
| C-5 | 일부 데이터를 빼거나 어긋나게 한 입력을 위임해, 추측 없이 그 사실을 보고하는지 본다. |

## 7. 리스크

| 리스크 | 대응 |
|---|---|
| 가설 시나리오가 실제 현장 문제와 다르다. | D-01에 따라 관계자 대화 뒤에 §3을 다시 쓴다. |
| 정제된 데이터의 형태를 몰라 입력 계약을 정할 수 없다. | 데이터가 확보될 때까지 spec으로 넘어가지 않는다. |
| 역할이 넓어져 에이전트 하나가 여러 책임을 진다. | 책임이 둘 이상으로 확인되면 에이전트를 나눈다(D-05). |

## 8. 미확인·이견

| ID | 미확인 사항 | 영향 받는 곳 | 확인 방법 |
|---|---|---|---|
| U-01 | 현장 문제와 에이전트가 맡을 실제 업무 | §1, §3, D-04 | 관계자 대화 |
| U-02 | 두 조합의 현재 업무 흐름과 담당자 | §2, §3 | 관계자 대화, 제공 자료 |
| U-03 | 에이전트를 만들 도구·호스트, 제출 형식, 평가 기준, 제한 시간 | §2, D-06 | 주최 측 안내 |
| U-04 | 에이전트의 수(통합 하나인지, 마을별인지) | D-05, C-4 | 주최 측 안내, 관계자 대화 |
| U-05 | 정제된 데이터의 형태와 위치 | §3 입력, spec의 입력 계약 | 데이터 확보 후 |

**이견.** 브리프는 참가자에게 "대화 → 데이터 수집·검증·정제 → 에이전트 구축"을 요구한다.
이 초안은 마지막 결과물인 조합 업무 개선 에이전트만 대상으로 삼았다.
앞의 과정(대화, 데이터 정제)을 대신 수행하는 에이전트가 필요한 것이라면 역할이 달라지므로 §1부터 다시 쓴다.
